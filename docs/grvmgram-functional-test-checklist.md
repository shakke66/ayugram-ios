# GRVMgram — журнал функционального тестирования

Актуальный ручной QA-чек-лист пользовательских функций GRVMgram для iPhone. Документ служит единым источником прогресса этого тестового прогона и обновляется после каждого ответа пользователя.

## Статусы

- `⬜ Не проверено` — тест ещё не выполнялся.
- `✅ Хорошо сделано` — функция полностью соответствует ожидаемому поведению.
- `🟡 Надо доработать` — функция работает, но рядом обязательно записывается конкретная доработка.
- `❌ Вообще не работает` — функция отсутствует, не запускается либо не даёт заявленного эффекта; рядом записывается наблюдаемое поведение.
- `➖ N/A` — Desktop-функция не имеет применимого iOS-аналога.
- `⏸ Не удалось проверить` — отсутствует необходимое внешнее условие, например реклама, Premium или тестовый бот.

## Правила ведения

1. Функции проверяются по ID сверху вниз.
2. После ответа пользователя меняются только статус и поле «Что доработать / наблюдение» соответствующей функции.
3. При `🟡` и `❌` записываются точные шаги, фактический результат и требуемое исправление.
4. Скриншоты и crash logs с персональными данными не добавляются в публичный репозиторий.
5. Разделы 9–10 старой базы знаний используются как каталог названий, но не как источник актуального статуса реализации.
6. Перед каждым тестом пользователю выдаются: точный путь по русскому UI, необходимые условия, пошаговые действия, ожидаемый результат и перечень сведений для ответа.

## Актуальное продуктовое требование к области настроек

- Все GRVMgram-настройки являются **едиными для установки клиента**, а не отдельными для Telegram-аккаунтов.
- Переключение аккаунта не должно менять app icon, Ghost, Filters, General, Appearance, Chats, Other или другие GRVM-настройки.
- Изменение настройки из любого аккаунта должно быть немедленно видно и применяться во всех остальных аккаунтах этого клиента.
- Account-scoped остаются пользовательские данные, для которых нужна изоляция: архив удалений, revisions, сохранённые media, read/action scope и другие данные конкретного Telegram-аккаунта.

## Текущая позиция

- **Следующие проверки:** ручной функциональный прогон завершён; `ST15–ST18` отправлены на доработку
- **Последние обновлённые функции:** `ST15–ST18 — ❌ Вообще не работает`; подтверждена связь недоступности read-actions `ST15–ST17` с неправильным runtime-gate мастера Ghost

## Подготовка тестового стенда

Для полного прогона желательно иметь:

- iPhone A с GRVMgram;
- аккаунт B на другом клиенте или устройстве;
- личный чат, group/supergroup и forum topic;
- broadcast-канал со связанным discussion и канал без него;
- бота с командами и inline callback-кнопками;
- Premium-пользователя;
- сообщения с photo, GIF, sticker, voice, round video, reply, spoiler, reactions и one-view media;
- несколько папок, custom wallpaper и локально загруженную музыкальную обложку.

## 1. AyuGram: Ghost Mode

### G01 — Мастер «Режим призрака»

- **Статус:** 🟡 Надо доработать
- **Что делает:** служит массовым переключателем и индикатором состояния отдельных Ghost-компонентов, но не является runtime-условием их работы. После удаления G07 управляет четырьмя компонентами и показывает `N/4`.
- **Как тестировать:** нажать мастер при `0/4` — включаются все четыре компонента и отображается `4/4`. Выключить один компонент — мастер автоматически гаснет и становится `3/4`, при этом оставшиеся три продолжают работать. Включить недостающий компонент вручную — мастер автоматически загорается. Нажать мастер для выключения — все компоненты становятся OFF. Дополнительно каждый компонент должен работать по собственному значению даже при выключенном мастере. После настройки на аккаунте A переключиться на B: значения должны сохраниться, поскольку GRVMgram-настройки глобальны для клиента.
- **Что доработать / наблюдение:** сейчас мастер является обязательным runtime gate: если верхний тумблер выключен, ни один включённый отдельный Ghost-компонент не действует. Требуется убрать эту зависимость: верхний тумблер только массово меняет значения и автоматически отражает состояние всех компонентов. Все проверки отдельных функций пользователь проводил с включённым мастером. Этот же неправильный gate делает недоступными read-actions `ST15–ST17`: `shouldSuppressReadReceipts` требует одновременно `ghostModeEnabled && suppressReadReceipts`; при выключенном мастере чат успевает очистить unread штатным чтением, suppression становится `false`, после чего пункты чтения не попадают в message/header menu. Также ранее подтверждён второй дефект: при смене Telegram-аккаунта загружается отдельный default snapshot, включая app icon; после возврата восстанавливаются значения основного аккаунта. Корневая причина account-scoped хранения уже подтверждена; нужен единый client-wide snapshot с миграцией, при сохранении изоляции архивов и других данных аккаунтов.

### G02 — Закреплённые компоненты Ghost

- **Статус:** 🗑️ Вырезать из форка
- **Что делает:** отдельный экран с пятью locks: «Отчёты о прочтении», «Просмотры историй», «Статус „в сети“», «Набор текста и загрузка», «Уход из сети после появления в сети». Если lock включён, мастер «Гост-режим» не изменяет соответствующий основной переключатель.
- **Как тестировать:** после удаления открыть: нижняя вкладка `Настройки` → `Настройки GRVMgram` → `Основное` → раздел `Гост-режим`. Строки `Закреплённые компоненты` и отдельного экрана locks быть не должно. Общий переключатель Ghost должен напрямую включать и выключать оставшиеся четыре компонента.
- **Что доработать / наблюдение:** принято продуктовое решение полностью удалить `Закреплённые компоненты` из iOS-версии. Это не соответствует назначению Desktop-функции, где закрепление даёт быстрый доступ к компонентам на боковой панели; применимого iOS-сценария для текущего механизма locks нет. Удалить строку, экран, счётчик `N/5` locks и саму логику исключения закреплённых компонентов из действия общего переключателя Ghost.

### G03 — Не отправлять отчёты о прочтении

- **Статус:** ✅ Хорошо сделано
- **Что делает:** подавляет server read receipts и content-consumed receipts, включая reply threads и topics.
- **Как тестировать:** B отправляет текст и voice; A открывает чат и проигрывает voice. У B не появляются отметки прочтения/прослушивания, локально контент открывается нормально.
- **Что доработать / наблюдение:** отчёты о прочтении и прослушивании успешно подавляются при включённом отдельном тумблере и текущем обязательном мастере Ghost. После исправления G01 повторно проверить независимую работу без master gate.

### G04 — Не читать истории

- **Статус:** ✅ Хорошо сделано
- **Что делает:** не регистрирует просмотр Story на сервере.
- **Как тестировать:** B публикует Story, A открывает её. После обновления списка зрителей у B аккаунт A отсутствует.
- **Что доработать / наблюдение:** приватный просмотр историй работает при включённом отдельном тумблере и текущем обязательном мастере Ghost. После исправления G01 повторно проверить независимую работу без master gate.

### G05 — Не отправлять Online

- **Статус:** ✅ Хорошо сделано
- **Что делает:** подавляет presence packets, рекламирующие Online.
- **Как тестировать:** B наблюдает статус A, пока A активно пользуется приложением 20–30 секунд. A не должен стать Online.
- **Что доработать / наблюдение:** подавление статуса «в сети» работает при включённом отдельном тумблере и текущем обязательном мастере Ghost. После удаления G07 этот компонент должен самостоятельно обеспечивать сохранение/возврат Offline после действий, включая отправку сообщения. После исправления G01 повторно проверить независимую работу без master gate.

### G06 — Не отправлять «Печатает/Загружает»

- **Статус:** ✅ Хорошо сделано
- **Что делает:** одним Ghost-компонентом подавляет typing и upload activity.
- **Как тестировать:** A печатает текст 10 секунд, затем загружает большой файл. У B нет статусов «печатает…» и «загружает…», готовое сообщение приходит.
- **Что доработать / наблюдение:** статусы набора текста и загрузки успешно подавляются при включённом отдельном тумблере и текущем обязательном мастере Ghost. После исправления G01 повторно проверить независимую работу без master gate.

### G07 — Автоматически уходить Offline

- **Статус:** 🗑️ Вырезать из форка
- **Что делает:** после реально отправленного Online сразу отправляет Offline; если Online был подавлен, лишний Offline не создаётся.
- **Как тестировать:** после удаления убедиться, что отдельной строки больше нет, счётчик мастера изменён с `N/5` на `N/4`, а включённый G05 самостоятельно сохраняет/возвращает Offline после отправки сообщения и других действий.
- **Что доработать / наблюдение:** принято продуктовое решение полностью удалить отдельный переключатель как бесполезный. Необходимое автоматическое сохранение/возвращение Offline должно быть встроенным поведением G05 «Не отправлять Online». Для сценария максимально полного Offline используется G09 «Использовать отложенные сообщения» совместно с G05.

### G08 — Читать при действиях / Read on Interact

- **Статус:** 🗑️ Вырезать из форка
- **Что делает:** после успешной отправки, реакции или poll vote помечает текущий чат прочитанным; взаимоисключается с G09. Server receipt продолжает подчиняться G03.
- **Как тестировать:** после удаления убедиться, что строки больше нет, отправка сообщения, реакция и голосование не изменяют read-state через удалённую GRVMgram-настройку, а G09 больше не связан с ней взаимоисключением.
- **Что доработать / наблюдение:** принято продуктовое решение полностью удалить функцию и связанную с ней настройку как бесполезные.

### G09 — Использовать отложку / Schedule Messages

- **Статус:** ❌ Вообще не работает
- **Что делает:** при Ghost задерживает text/forward/existing media на 12 секунд, voice/round video на 17 секунд, новый файл по формуле `max(19, 13 + max(6, ceil(MiB × 0.7)))`; при proxy задержка умножается на `1.2` с округлением вверх.
- **Как тестировать:** включить G05 и G09, затем с секундомером отправить text, voice и новый файл; повторить при G09 OFF. При включённой отложке должны соблюдаться заявленные задержки, при выключенной сообщения уходят штатно. Удалённая G08 больше не должна влиять на функцию.
- **Что доработать / наблюдение:** при ручной проверке с включённым мастером Ghost функция не дала заявленного эффекта. Требуется отдельное воспроизведение с фиксацией типа сообщения, фактического времени отправки и сочетания с G05 до поиска корневой причины. Целевой сценарий: совместно с «Не отправлять Online» автоматически отправлять исходящие как отложенные, чтобы не раскрывать Online.

### G10 — Отправлять без звука

- **Статус:** ❌ Вообще не работает
- **Что делает:** режимы Never, In Ghost и Always управляют silent-флагом исходящих сообщений.
- **Как тестировать:** B включает звук уведомлений. Для каждого режима отправить сообщения без активных Ghost-компонентов и хотя бы с одним активным компонентом: Never всегда со звуком, In Ghost без звука при активном Ghost-сценарии, Always всегда без звука. Проверка не должна зависеть от отдельного stored-значения мастера G01.
- **Что доработать / наблюдение:** по результату ручной проверки функция вообще не влияет на звук уведомления у получателя даже при включённом мастере Ghost. Перед исправлением нужно воспроизвести отдельно режимы Never, In Ghost и Always и зафиксировать outgoing silent-флаг, чтобы установить корневую причину.

### G11 — Предлагать Ghost перед просмотром Story

- **Статус:** ✅ Хорошо сделано
- **Что делает:** до первого view receipt показывает выбор Enable Ghost Mode или View Normally; один prompt на открытый Story-screen.
- **Как тестировать:** Enable Ghost открывает Story без появления A у B среди зрителей; View Normally даёт ровно один просмотр. На следующей Story того же экрана повторного prompt нет.
- **Что доработать / наблюдение:** предложение включить Ghost перед просмотром истории появляется и работает корректно.

## 2. Spy Mode, архив и History

### SP01 — Сохранять удалённые сообщения

- **Статус:** 🟡 Надо доработать
- **Что делает:** сохраняет inline и в архиве известные локальному клиенту удалённые сообщения других участников; исходящие сообщения текущего аккаунта после удаления не сохраняются и не показываются.
- **Как тестировать:** B удаляет свои text и photo в DM, group/supergroup и topic — они остаются inline и появляются в соответствующем архиве. A удаляет собственное исходящее сообщение — оно исчезает штатно и отсутствует inline, в архиве и поиске. После relaunch результат сохраняется. При OFF новые удаления любых авторов исчезают штатно.
- **Что доработать / наблюдение:** механизм сохранения работает, но сейчас также показывает удалённые сообщения, автором которых является текущий аккаунт. Требуется единый author-filter для inline-показа, архива и поиска: сообщения `author == current account` не сохранять и не отображать независимо от способа удаления.

### SP02 — Сохранять историю правок

- **Статус:** ✅ Хорошо сделано
- **Что делает:** сохраняет входящие и исходящие revisions конкретных сообщений.
- **Как тестировать:** A и B несколько раз редактируют разные сообщения. History каждого показывает только его старые и текущую версии; при OFF новые revisions не добавляются.
- **Что доработать / наблюдение:** сохранение истории правок работает исправно.

### SP03 — Сохранять в чатах с ботами

- **Статус:** ✅ Хорошо сделано
- **Что делает:** разрешает сохранение удалений в прямом диалоге с ботом; не должно управлять edit history.
- **Как тестировать:** контролируемый бот отправляет и удаляет сообщение. При OFF оно исчезает, при ON остаётся inline/archive. В группе bot-delete не должен зависеть от этого switch.
- **Что доработать / наблюдение:** сохранение удалений в чатах с ботами работает исправно.

### SP04 — Локальный Telegram Premium

- **Статус:** ✅ Хорошо сделано
- **Что делает:** локально включает Premium UI только для exact current account, не выдавая серверные возможности.
- **Как тестировать:** включить на непремиальном A. Premium-индикатор появляется у A, но не у обычного B; настоящий Premium другого пользователя сохраняется; серверно платная операция остаётся ограниченной.
- **Что доработать / наблюдение:** локальное включение Premium работает. Отсутствующая межклиентская синхронизация Desktop-версии вынесена отдельно в SP04A, чтобы не смешивать её с работоспособностью локального тумблера.

### SP04A — Синхронизация локального Premium между GRVMgram-клиентами

- **Статус:** ❌ Вообще не работает
- **Что делает:** позволяет другому пользователю GRVMgram видеть локальный Premium собеседника и поддерживаемое Premium-оформление/состояние, включая отправленные Premium emoji и stickers, как в Desktop-версии клиента.
- **Как тестировать:** использовать два непремиальных аккаунта A и B на двух GRVMgram-клиентах. Включить локальный Premium только у A, затем на B проверить Premium-индикатор и поддерживаемые Premium-настройки профиля A; отправить с A Premium emoji и sticker и проверить их отображение на B. Повторить после выключения функции и перезапуска обоих клиентов. Перед реализацией восстановить по Desktop-коду точный перечень синхронизируемых полей и не смешивать их с приватными настройками самого клиента.
- **Что доработать / наблюдение:** функция межклиентской синхронизации, присутствующая в AyuGram Desktop, в текущей iOS-версии отсутствует. Нужна полная отдельная портировка после анализа Desktop-протокола и границ синхронизируемых Premium-данных.

### SP05 — Отключить рекламу

- **Статус:** ✅ Хорошо сделано
- **Что делает:** скрывает sponsored messages и promo rows, не затрагивая обычные сообщения.
- **Как тестировать:** найти канал/поиск, где Telegram реально выдаёт рекламу, и сравнить OFF/ON. Если реклама аккаунту не выдаётся, поставить `⏸ Не удалось проверить`.
- **Что доработать / наблюдение:** скрытие рекламы работает исправно.

### AR01 — Глобальный архив удалённых сообщений

- **Статус:** 🗑️ Вырезать из форка
- **Что делает:** в целевом интерфейсе глобального объединённого архива нет; удалённые сообщения открываются только из профиля конкретного диалога.
- **Как тестировать:** после переделки открыть `Настройки GRVMgram` и убедиться, что глобальная строка `Удалённые сообщения` удалена. В интерфейсе не должно остаться экрана, смешивающего записи из разных диалогов.
- **Что доработать / наблюдение:** принято продуктовое решение убрать глобальный архив из настроек. Пользователю не нужен общий список удалений из всех чатов; доступ должен быть только к архиву выбранного диалога через AR02.

### AR02 — Архивы GRVMgram в профиле чата/topic

- **Статус:** 🟡 Надо доработать
- **Что делает:** из профиля конкретного диалога открывает архив только для `current account + dialog + optional topic` и показывает в нём только удалённые сообщения других участников.
- **Как тестировать:** открыть профиль личного чата. Под строкой `О себе` и над переключателем `Публикации / Подарки / Медиа` должна находиться отдельная строка `Архивы GRVMgram`, визуально оформленная как строка `ID` и отделённая divider.
